NetSilcon-64x6 Neural-Network Inference Engine

with 22,528 Loadable Weights, Block-RAM Weight Banks and UART Interface

1Features

  • Hardware neural network: fixed 16 → 64 → 64 → 64 → 64 → 64 → 64 → 16 architecture: 16 inputs, 6 hidden layers of 64 neurons, 16 outputs
  • Loadable model: 22,928 parameters (22,528 int8 weights and 400 int16 biases) plus 7 per-layer shifts, in a 23,335-byte model image
  • Predictable latency: 448 clock cycles per inference, every inference (16.6 µs at 27 MHz)
  • 64 MAC lanes: one input broadcast per clock to 64 multiply-accumulate lanes; 50.3 multiply-adds per clock on average
  • Bit-exact: results match the Python integer reference model bit for bit (3,200 test vectors on hardware)
  • Two weight banks: a new model is written into the inactive bank while the running model keeps working; the banks swap in one clock
  • Safe model update: image protected by CRC-32; a damaged, incomplete or out-of-range image is refused and the running model is untouched
  • Host interface: UART, 115 200 baud, 8N1; inference, model upload, model information and link-test commands
  • Status LEDs: heartbeat, answer, upload, active bank, uploaded model, error
  • Small footprint: 35 % of the logic of a Gowin GW2AR-18; 32 block RAMs, 16 DSP blocks
  • Timing margin: 61.5 MHz maximum frequency in the Gowin timing analysis, against 27 MHz used
  • Open source: RTL, tools, models and test logs under the Apache License 2.0

2Applications

  • Robot and rover obstacle avoidance from multi-sector LiDAR or range-sensor arrays
  • Multi-class fault classification (up to 16 classes) in motor drives, pumps and compressors
  • Battery-pack monitoring across up to 16 cells or features
  • Vibration and acoustic feature classification for predictive maintenance
  • Multi-sensor fusion and plausibility checks beside a safety MCU
  • Gesture and activity recognition from IMU feature vectors
  • Small control policies with up to 16 outputs

3Description

NetSilcon-64x6 runs a 7-layer neural network in dedicated FPGA hardware. The network shape is fixed in the logic. The weights, biases and shifts are uploaded over UART, so the same bitstream does a different job by loading a different 23,335-byte model.

The host sends 16 input bytes and receives 16 signed outputs, the index of the largest output and the measured latency. There is no instruction fetch, no operating system and no cache: every inference takes exactly 448 clock cycles.

NetSilcon-64x6 is the larger member of the NetSilcon family. NetSilcon-6x4 (4 → 6×4 → 2, 15 cycles) wires every neuron in parallel; NetSilcon-64x6 instead keeps its weights in block RAM and reuses 64 lanes for every layer, which lets a network with 22,928 parameters, about 135 times the 6x4's 170, fit in less logic on the same FPGA.

7Detailed description

7.1 Overview

NetSilcon-64x6 has five functional blocks: the UART interface, a frame decoder, the model loader, the neural engine with its weight RAM, and the reply builder. All run in one 27 MHz clock domain. The engine is idle until an inference request arrives and computes one inference at a time.

7.2 Network architecture

Table 7-1. Layers

LayerInputsNeuronsWeightsBiasesActivationOutput range

Total: 22,928 parameters (weights + biases), plus 7 layer shifts. Every model for NetSilcon-64x6 has exactly this size.

7.3 Lane datapath

Lane j is neuron j of every layer. Each clock, one input value xi is broadcast to all 64 lanes, and each lane adds xi · wj,i, its own weight, to its 24-bit accumulator. For a layer with Nin inputs:

Table 7-2. Clock schedule of one layer

ClockWeight RAM word readLane operation
t = 0bias, low byteacc = bias_lo
t = 1bias, high byteacc += bias_hi × 256
t = 2 … Nin + 1weight i = t − 2acc += xi × wi
t = Nin + 2, Nin + 3–pipeline drain

Each layer therefore takes Nin + 4 clocks: (16 + 4) + 6 × (64 + 4) = 428 clocks for the seven layers, plus 19 clocks to pass the 16 outputs through the requantizer and 1 clock of control, giving 448.

Figure 7-1. Lane datapath and the layer-to-layer loop

7.4 Shared requantizer

At the start of the next layer all 64 sums are copied in one clock into a 64 × 24-bit shift chain. The chain feeds one sum per clock into a single two-stage requantizer (ReLU and rounding constant, then arithmetic shift and clamp). Its int8 output arrives exactly when the matching weight of the next layer is read. One requantizer instead of 64 saves 63 barrel shifters.

7.5 Weight memory and banks

The 22,528 weights and 400 biases live in 32 simple-dual-port block RAMs of 1K × 16 bits. Each 16-bit word holds the bytes of two lanes (lane 2k in the low byte, lane 2k + 1 in the high byte), so one shared read address delivers 512 bits per clock, a byte for every lane. Address bit 9 selects the bank: bank 0 holds the built-in model from the bitstream, bank 1 receives uploads. The read enable is active only while the engine computes.

7.6 Model upload and bank swap

The loader writes an incoming image straight into the inactive bank, pairing lanes into full 16-bit words, while the running model stays usable. It computes the CRC-32 over the received bytes. Only if the CRC matches, all 23,335 bytes arrived and every shift is 0 … 23 does it flip the bank bit, in one clock, after any running inference finishes. Inference requests are not accepted while an upload is in progress.

8Mathematical model

8.1 Neuron equation

Every neuron computes, in integer arithmetic identical to the Python reference model python/model/ns64.py:

acc = b + Σ (x_i × w_i) x_i, w_i : int8 b : int16 acc : 24-bit signed a = max(acc, 0) hidden layers (ReLU); output layer: a = acc v = (a + 2^(s−1)) >>> s s = layer shift 0 … 23; no rounding constant when s = 0 y = clamp(v, 0, 127) hidden layers y = clamp(v, −128, 127) output layer

Inputs to the device are 0 … 127. A real-world value is scaled as q = round(value / full_scale × 127).

8.2 Accumulator range

A hidden-layer neuron adds 64 products of at most 127 × 127 plus a 16-bit bias, so its sum needs at most 21 bits plus sign; the accumulator has 24. The stress test model (all weights −128 or +127, biases at the int16 limits) reaches layer sums of 1,008,128 and still matches the reference on hardware (200 / 200 vectors).

8.3 Quantization

Models are trained in floating point and converted after training:

  1. Each layer's weights are scaled by K = 127 / max|W| and rounded to int8.
  2. Biases are scaled with the same factors and stored as int16.
  3. Each layer's shift s is the smallest that keeps 99.99 % of that layer's activations within 0 … 127 on calibration data.
  4. For regression outputs, the last layer is scaled so that the output equals value × 127.

8.4 Outputs

The device returns all 16 signed outputs and their argmax (index of the largest, the first if several are equal, like numpy.argmax). Classifiers use the argmax; regression models read y / 127 as a value from −1 to +1. Unused outputs can be set to exactly 0 by zero weights and biases.

8.5 Latency and clock cycles

Latency in microseconds is 448 / fclk: 16.6 µs at 27 MHz, 7.3 µs at the 61.5 MHz timing limit (E). The cycle count does not depend on the input values or the model.

10.3 Built-in model

Bank 0 is initialised from the bitstream with the synthetic test model (CRC-32 6F4225BF): random weights with shifts calibrated so that about 30 % of hidden activations are 0, under 1 % saturate and about 7 % of outputs reach +127 or −128. It exists to prove the hardware. Uploaded models live in block RAM and are lost at power-off.

12Application and implementation

12.1 Typical application

A host (a PC in the reference set-up, an MCU in a product) scales up to 16 features to 0 … 127, sends them with A5 and reads back 16 outputs and the argmax. A new model is uploaded once with C3 and stays active until power-off.

12.2 Example design: rover obstacle avoidance

The first trained NetSilcon-64x6 model drives a differential-drive rover from a 360° LiDAR scan. The scan is reduced to 16 sectors of 22.5°; each input is the smallest distance in its sector, measured from the rover's body edge, with 0 … 4 m mapped to 0 … 127 (about 3.1 cm per step).

y1Steering × 127, positive = left

12.3 Other applications

Any job with up to 16 inputs and up to 16 outputs fits: multi-class fault classification, battery-cell monitoring, vibration features, sensor fusion. These are application ideas; trained models for them do not exist yet (T).

15Reliability and safety

15.1 Built-in safety features

  • CRC-32 over every uploaded image; refused uploads never touch the running model.
  • Two weight banks: no half-loaded state is ever used for inference.
  • Shift range check (0 … 23) before a model goes live.
  • Frame timeout: a stalled frame cannot lock the interface.
  • Fixed latency: 448 cycles regardless of input or model.
  • Error LED latched until reset.

15.2 Use in safety-related systems

NetSilcon-64x6 is a prototype. It is not designed or certified as the sole protection in life-support, automotive, aviation or other safety-critical systems. Use it beside proper safety logic. In the rover tests, the safety stop that prevents collisions is separate fixed logic, not the network.
